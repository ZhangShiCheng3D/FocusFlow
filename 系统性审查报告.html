需处理项

✅ 音效资产 bug 已修：clock_tick.aac 之前实际只有 ~30ms

ci_generate_sounds.sh:50 / generate_sounds.sh:80 旧 sine d=0.03 源在 30ms EOF，-t 60 拉不长 → 成品 ~30ms，循环成蜂鸣。

修复：改为周期脉冲 aevalsrc=0.25*sin(2*PI*1000*t)*lt(mod(t,1),0.03):d=120:s=44100（每秒一次 30ms 滴答）。本机 ffmpeg 实测确认：产出 60.02s、整 60 个起音；两脚本 bash -n 通过。

⚠️ 脚本已修，但用户侧生效还需你触发一次重灌：打 sounds-v2 tag 跑 upload-sounds.yml，再更新 Models.swift:54 的 tag 名。上传是对外发布动作，未擅自触发。

✅ CI 密钥内联已修

app-store-submit.yml 把 APP_STORE_CONNECT_API_KEY_BASE64 从 run: 内联改为经 step env: 注入、脚本用 $VAR 引用，与其余证书/密码一致。

🟠 安全：Keychain 失败时 OAuth Token 明文落入 UserDefaults

IntegrationManager.swift KeychainManager.save/get 在 SecItemAdd 失败时回退到 UserDefaults（明文 plist）存放 Token。已有"成功即清除回退"的缓解，但失败窗口内 Token 以明文存在。

建议：沙盒生产环境 Keychain 几乎不会失败，风险低。可考虑回退时改存内存（会话级）或直接放弃同步并提示，而非落盘。优先级中低，属设计权衡（CLAUDE.md 已记录其为模拟器兜底）。

观察项（非缺陷，供参考）

  • OAuth 为代理全托管：客户端 performOAuthPKCE 不持有 PKCE verifier，握手全在 Cloudflare Worker。这是有意设计（CLAUDE.md 明示），意味着代理被完全信任——属架构选择，非漏洞。
  • 合成音效偏简陋：piano/choir/wind_chime 等"音乐"类是纯正弦音（如 piano=440Hz 正弦）。对白噪声 App 尚可，但作为差异化卖点偏弱——产品/资产决策，非代码问题。
  • altool 已被 Apple 标记弃用：submit_app_store.sh 用 xcrun altool --upload-app，仍可用，未来宜迁移到 notarytool/Transporter。
  • 文档轻微重复：CLAUDE.md 与 AGENTS.md 内容大面积重叠，维护时易不同步。
  • Manager 异步测试缺口（延续上轮 P3）：StatisticsManager 聚合、FocusStateManager 会话序列仍无测试。
