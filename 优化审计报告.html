P0 · 真实功能性 Bug

已修复

全局快捷键：已实现并接线（原为"假功能"）

原问题：设置里有开关 + 录制框，但 registerHotkey() 只有一行 print()，handleHotkey()/.shared 全项目从未被调用——用户开开关、按键后什么都不会发生。

本次改动（采用方案 ①）：

  • 新增 HotKeyCombo 解析器：把 "⌘⌥F" 解析为 Carbon 虚拟键码 + 修饰符掩码，非法组合返回 nil。KeyboardHandler.swift
  • 重写 GlobalHotkeyManager：用 RegisterEventHotKey（无需辅助功能权限）+ Carbon 事件回调，按下时跳回主线程调用 handleHotkey() → startFocus()。
  • 把设置里没法用的自由文本框换成真正的 HotkeyRecorderField 录制控件。GeneralSettingsView.swift
  • 接线：AppDelegate 启动时注册；useGlobalHotkey/hotkeyCombo 变更时经 applyHotkey() 重注册；resetAll() 显式注销。
  • 新增 3 个解析器纯逻辑单测（CI 可验证）。
⚠️ 验证边界：我在 Windows 上只能保证代码正确性，CI（macOS runner）可验证编译 + 单测。但热键运行时能否真正触发，需你在 Mac 上实测一次。

P1 · 健壮性 / 隐式耦合

P1

ODR 下载进度依赖「soundId == 文件名去掉 .aac」的隐式约定

URLSessionDataDelegate 的三个回调都通过 url.lastPathComponent.replacingOccurrences(of:".aac") 反推 soundId ODRManager.swift:170,180,194。今天目录里所有 id == fileName 去后缀，能跑通；但这是脆弱耦合：未来若某个音效 id ≠ fileName，进度条与完成回调会静默失效（continuation 永不 resume → 下载 await 卡死）。

建议：用 task.taskIdentifier → soundId 的映射表显式传递，移除字符串反推。改动小、可纯靠代码审查验证。属于"加固"而非"修 bug"，可选。
P1

专注中切换预设，统计记录的仍是开始时的音效组合

applyPreset() 在会话进行中会停止并重启音效 PopoverContentView.swift:292，但 FocusStateManager.currentSessionSoundIds 在 startFocus() 时即捕获、结束时才写入统计。中途换预设不会更新，统计里记的是旧音效。

建议：影响很小（仅统计字段精度），可记为已知行为，或在 applyPreset 中同步更新会话音效。优先级低。
